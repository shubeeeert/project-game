# Отчёт: интеграция ИИ-модулей в проект «ill try»

Дата проверки: 18.11.2026
Статус: **ИИ интегрирован и реально работает в игре** (подтверждено headless-верификацией и запуском живой игры через редактор Godot).

---

## 1. Краткое резюме

В проекте используются **три обученные нейросетевые модели** (компактные MLP), которые участвуют в процедурной генерации этажей:

| Модель | Архитектура | Что предсказывает | Где применяется |
|---|---|---|---|
| `structure` | 6 → 16 → 16 → 3 (sigmoid) | число комнат, длину «позвоночника», наличие циклов | макрогенерация графа этажа |
| `tile` | 7 → 16 → 16 → 15 (sigmoid) | карту плотности препятствий 5×3 (15 блоков) | интерьеры комнат (камни, ямы, шипы) |
| `enemy` | 8 → 6 → 1 (sigmoid) | «привлекательность» клетки для размещения врага | расстановка врагов по комнате |

Обучение выполняется **офлайн** (numpy, без ML-фреймворков), а в игре идёт **детерминированный inference на чистом GDScript** — никаких внешних зависимостей, сети или глобального RNG. Веса хранятся в `data/generation/ai_models.json` (версия 3, ~11.6 КБ).

ИИ включён **по умолчанию**: в `data/generation/generation_config.json` задано
`algorithms: { macro: "ai_structure", interior: "ai_tile_model", entities: "ai_placement" }`.

## 2. Архитектура интеграции

### 2.1. Файлы ИИ-модулей

```
scripts/generation/ai/
├── ai_model_runtime.gd        — загрузка весов и inference (общий для всех моделей)
├── ai_structure_generator.gd  — макрогенератор этажа (модель structure)
├── ai_interior_generator.gd   — генератор интерьера (модель tile)
├── ai_entity_placer.gd        — обёртка размещения врагов (модель enemy)
└── ai_cell_picker.gd          — оценка и сортировка клеток моделью enemy

tools/
├── export_training_data.gd    — сбор обучающей выборки (офлайн)
└── train_ai_models.py         — обучение моделей (офлайн, numpy)

data/generation/
├── training_floors.json       — обучающая выборка
└── ai_models.json             — веса трёх моделей (version 3)
```

### 2.2. Пайплайн обучения (офлайн, в игре не выполняется)

1. **`tools/export_training_data.gd`** генерирует 270 этажей (90 seed × 3 этажа) классическим генератором и экспортирует в `training_floors.json`:
   - для модели `structure`: латентный вектор z (4 числа) + условия этажа → фактические параметры графа (комнаты, позвоночник, циклы);
   - для модели `tile`: 3654 комнаты — тип, маска дверей, сложность, z → фактическая плотность препятствий по 15 блокам внутренней области 11×5;
   - для модели `enemy`: 158 304 примера клеток — признаки клетки → был ли там размещён враг.
2. **`tools/train_ai_models.py`** обучает три малых MLP на numpy и сохраняет веса в `ai_models.json` вместе с метаданными (`feature_spec`, объёмы выборки).

Метаданные из актуального `ai_models.json`:
```json
{
  "source": "tools/export_training_data.gd",
  "floors": 270,
  "tile_rooms": 3654,
  "enemy_samples": 158304,
  "framework": "numpy (offline), GDScript inference",
  "feature_spec": { "structure": 6, "tile": 7, "enemy": 8,
                    "tile_outputs": 15, "block_cols": 5, "block_rows": 3 }
}
```

### 2.3. Runtime inference — `ai_model_runtime.gd`

- Ленивая загрузка `ai_models.json` при первом обращении (`_load()`), кэш на весь процесс.
- Веса разворачиваются в плоские `PackedFloat32Array` (row-major) — без Variant-оверхеда в горячем цикле.
- `forward()` / `forward_packed()` — прямой проход с relu/sigmoid; `forward_softmax_packed()` — для softmax-выходов.
- Если файл весов отсутствует или повреждён, `is_available()` возвращает `false`, и каждый генератор **прозрачно откатывается** на классический алгоритм (игра не ломается).

### 2.4. Подключение к оркестратору

`generator_factory.gd` создаёт алгоритмы по именам из конфига:
- `create_macro("ai_structure")` → `AIStructureGenerator`;
- `create_interior("ai_tile_model")` → `AIInteriorGenerator`;
- сущности: `FloorGenerator._populate_floor()` при `algorithms.entities == "ai_placement"` вызывает `AIEntityPlacer.populate()` вместо классического `EntityPlacer.populate()`.

Оркестратор `floor_generator.gd` не знает, какой алгоритм внутри: макро → роли комнат → двери → замки → интерьеры + сущности → ключи → валидация → автопочинка. Все ограничения (START/BOSS, достижимость, двери у соседей, спецкомнаты с одним соседом, бюджеты) проверяются **одинаково** для ИИ и классики.

## 3. Как работает каждая модель в игре

### 3.1. Модель `structure` — граф этажа

Файл: `ai_structure_generator.gd`.

1. Вход (6 признаков): `floor_index/3`, `difficulty/3` и **4 числа латентного вектора z из seeded RNG** (`rng.next_float()`).
2. Выход (3 числа, sigmoid) декодируется в параметры:
   - `target_rooms = clamp(round(9 + out[0]*12), min_rooms, max_rooms)`;
   - `spine_length = clamp(round(2 + out[1]*8), 2, target_rooms-1)`;
   - `allow_loops = out[2] >= 0.5` (и только если разрешено конфигом).
3. Параметры подставляются в tuning, и граф строит **классический ограниченный генератор `spine_branch`**. То есть ИИ управляет «формой» этажа, а жёсткие инварианты (связность, двери, босс-лист) обеспечивает проверенный алгоритм.
4. В метаданные этажа пишутся `algorithm: "ai_structure"` и `ai: { model, params (включая z и сырой выход), model_meta }`.

### 3.2. Модель `tile` — интерьеры комнат

Файл: `ai_interior_generator.gd`. **Один вызов модели на комнату** (не на клетку) — ключевое условие бюджета производительности.

1. Базовый проход (`interior_generator.gd` с `defer_connectivity`) готовит структуру: стены, двери, пьедесталы, типы.
2. Шаблонные препятствия во внутренней области (x 1..11, y 1..5) удаляются (`_clear_learned_tiles`).
3. Вход модели (7 признаков): индекс типа комнаты / 10, маска дверей / 15 (биты north/south/west/east), `difficulty/3`, 4 числа z из RNG.
4. Выход — 15 вероятностей (карта плотности 5×3). Каждая клетка внутренней области относится к своему блоку (`_block_of`).
5. Разворачивание (`_apply_layout`): для каждой свободной клетки шанс препятствия = `max(0.07, p_блока) + jitter(±0.09)` из RNG; 22% препятствий становятся опасностями (шип/яма), остальные — камни.
6. **Зарезервированные клетки не засоряются**: дверные проёмы и внутренние зоны дверей, пьедесталы, центральная арена босса. Для START/BOSS/TREASURE/SHOP планировка фиксированная (список `AI_ROOM_TYPES`).
7. **Жёсткое восстановление проходимости** (не отключается настройками): двери освобождаются, все входы связываются BFS-компонентой, при необходимости прорубаются коридоры (`_ensure_all_doorways_connected`, счётчик `doorway_repairs`).
8. Комната получает `template_id: "ai_tile_model"`, тег `ai_generated` и метаданные `ai_interior: { model, blocks, obstacles, hazards, doorway_repairs, available }`.

### 3.3. Модель `enemy` — размещение врагов

Файлы: `ai_entity_placer.gd`, `ai_cell_picker.gd`.

1. `AICellPicker.build()` собирает допустимые клетки (проходимые, вне безопасной зоны входа, достижимые).
2. Каждая клетка оценивается моделью (8 признаков): тип комнаты, сложность, нормированные x/y, число дверей, расстояние до ближайшего входа, класс тайла, число опасных тайлов в окрестности 3×3. Признаки комнаты вычисляются один раз, буфер переиспользуется.
3. Клетки сортируются по `score + rng.next_float()*0.12` — детерминированный «шум» даёт разнообразие при том же seed.
4. Дальше работает **классический `EntityPlacer`**: бюджеты сложности, лимиты типов, безопасная зона, минимальные дистанции. ИИ заменяет только порядок выбора клеток, поэтому все ограничения сущностей сохраняются.
5. Комната получает маркер `ai_entities: { model: "enemy", available: true }`.

## 4. Сквозной путь ИИ-данных до игрового процесса

```
main.tscn (_ready)
  → RoomManager.start_run(seed)
    → MapGenerator.generate_map()          [use_procedural_generator = true]
      → RunGenerator.generate_floor({seed, floor_index, config, balance})
        → FloorGenerator:
            macro      = ai_structure      (модель structure → параметры графа)
            interior   = ai_tile_model     (модель tile → камни/ямы/шипы)
            entities   = ai_placement      (модель enemy → позиции врагов)
            + валидация/починка (без изменений)
      → RoomPayloadAdapter.to_map_payload()  (домен → формат RoomGrid 13×9)
    → MapGenerator.rooms (payload: doors, obstacles, enemies, items…)
  → RoomManager._load_room_internal()
    → room.gd setup():
        _spawn_obstacles()  — инстанциирует rock/spike/pit из AI-данных
        _spawn_enemies()    — враги на AI-позициях (SHOP/TREASURE без врагов)
  → enemy.gd + enemy_navigation.gd — A* обходит AI-препятствия
```

Таким образом, предсказания моделей напрямую превращаются в игровые объекты: камни, ямы и шипы в комнатах, позиции врагов и форму этажа на миникарте.

## 5. Гарантии и ограничения

- **Детерминизм**: весь случайный выбор — только через seeded RNG (`deterministic_rng.gd`); глобальные `randi()/randf()` в генерации не используются. Один seed → идентичный этаж (проверено хэшем структуры).
- **Fallback**: при отсутствии/несовпадении размеров моделей генераторы молча переходят на классику (`spine_branch`, `template_interior`, `budget_placed`).
- **Валидация не отключается**: ИИ-этажи проходят тот же набор валидаторов (граф, двери, смежность, спецкомнаты, интерьеры, сущности, замки/ключи, бюджеты).
- **Производительность**: tile вызывается один раз на комнату; веса в плоских массивах; целевой бюджет p95 < 50 мс на этаж (нагруженность машины может влиять на замеры, но алгоритмическая стоимость мала).
- **Спецкомнаты**: START/BOSS/TREASURE/SHOP сохраняют фиксированную планировку; ИИ-зашумление применяется только к NORMAL.
- **Ресурсы**: inference — чистый GDScript, без сети, без autoload-зависимостей, без внешних библиотек; файл весов ~11.6 КБ.
